Observations from a live agent-interface session, Claude, 2026-07-28.

Written from the read-only agent API against a running instance. Nothing here
was edited -- these are findings and suggestions for a later session, for
whoever picks it up, Claude or Codex. Severity is my own judgement.

Live state at the time: Qwen3-4B-Abliterated-Q8_0 / CUDA, director role,

================================================================
1. /ask confabulates conversation history it cannot see   [HIGH]
================================================================

/ask has no access to the operator's live chat or conversation history. This
is deliberate and documented. But the model answers history-referential
questions as though it remembered them.

    Q: What were we working on last time we spoke?
    A: I was working on the project's development and maintenance. The last
       conversation was about the creator's goals and the system's
       capabilities.

There was no such conversation in its context. It cannot have known.

The knowledge is present but unapplied. Asked directly, it is correct:

    Q: Do you have access to our conversation history right now?
    A: No. I do not have access to our conversation history right now.

And a sharply-worded version is answered honestly:

    Q: What was the last thing I said to you, word for word?
    A: I cannot recall the exact words of your previous message. However,
       the last message you sent was: "What was the last thing I said to
       you, word for word?"

    -- which is actually correct: within /ask, that IS the only message.

So the failure is narrow and specific: vague temporal reference ("last time",
"earlier", "before") invites a fluent invention, while an explicit question
about capability gets the truth.

This is the same bug class as the PERSONA_SHOTS fusion fixed in Beta 6, in a
path that fix did not cover. The Beta 6 lesson applies unchanged: do not ask
the model to be honest about it, make the false answer unreachable.

SUGGESTED EDIT (not applied)
  In the /ask path only, detect history-referential phrasing the same way
  near_miss_command() detects near-miss commands -- in Python, narrow, with
  a fixed response. Either prepend a system line stating that this mode has
  no conversation history, or prefix the answer with that fact.

  Prefer the prefix. A system line is advice the model may ignore, which is
  precisely the reasoning that already failed once here.

  Keep the trigger list short and literal: "last time", "earlier", "before",
  "we talked", "we discussed", "you said", "remember when". A false positive
  costs one unnecessary disclaimer sentence. A false negative is a fabricated
  memory presented to another agent as fact.

2. Health check reports an unauthenticated model API   [MEDIUM]
================================================================

    /health blockers: ["the model API is answering without authentication"]

The local llama-server accepts requests with no auth. On a single-user
desktop with a loopback bind this is low risk, but it is a standing blocker
the health check itself raises, and the agent interface right beside it does
require a bearer token. The asymmetry is worth resolving or documenting as
accepted.

Worth checking whether that server is bound to loopback only. If it is, this
is a documentation item. If it is not, it is more than that.

3. Offline library reports embedded: 0    [MEDIUM]
================================================================

    offline_library: { ready: true, sources: 8, chunks: 15, embedded: 0 }

15 chunks, none embedded, while memory search reports retrieval mode
"hybrid" -- so the embedder itself is up and serving. Knowledge search
returns good lexical results, so nothing is visibly broken.

But it means knowledge reranking and the labelled "semantic-candidate" path
are, in practice, not doing anything on this install. That is a documented
feature that is currently inert.

Determine which it is:
  (a) embeddings are computed lazily and 0 is expected until first use, or
  (b) knowledge chunks are never embedded on import.

If (a), consider reporting it as "embedded: 0 (lazy)" so the number stops
looking like a fault. If (b), it is a real gap between documentation and
behaviour.

Testing notes for whoever continues
================================================================

- /ask holds the same model slot as the human session and yields to the
  operator. Use a slow, finite retry. Do not poll it.
- Queries are capped at 400 characters and answers at 128 generated tokens,
  so probes must be short and answerable briefly.
- The bearer token is at assistant\.agent_token. Do not put it in a URL;
  URLs survive in shell history and logs.
- Nothing on this interface writes. Every observation above is read-only.

8. Unknown routes list their alternatives under HTTP 404  [CONFIRMED]
================================================================

The first client observation recorded only the HTTP 404 from a GET to
/not-a-route. Source inspection shows the route handler also returns a JSON
body containing the current route list, exactly as the guide says. The
apparent mismatch was the PowerShell client's normal treatment of any non-2xx
response as an exception before its body is surfaced.

SUGGESTED DOC CLARIFICATION (not applied)
  Say explicitly that the route list accompanies an HTTP 404. Clients should
  read the JSON error body rather than treating the status alone as the
  complete response.


================================================================
9. Memory-search results lack the knowledge-search metadata  [LOW]
================================================================

The non-sensitive test query returned retrieval: hybrid and one memory
candidate, but the candidate was a bare string. In contrast,
/knowledge/search returns title, heading, review and staleness fields,
retrieval label, similarity, and source metadata. The current difference is
not necessarily wrong, but it leaves an agent unable to tell why a memory
candidate was selected or how tentative it is without treating its text as
evidence.

The source now adds an explicit top-level note: "memory results are retrieval
candidates, not verified facts." The running Sable process still has the
older code until its operator next restarts it.

SUGGESTED EDIT (not applied)
  Document the memory-search result schema explicitly. If practical, return
  small per-candidate metadata such as retrieval label, similarity or score,
  and a stable identifier, while retaining the existing bounded text.


================================================================
10. /ask overstates its verification and configuration access  [MEDIUM]
================================================================

Asked what the read-only API can reliably do, Sable said it can "view project
configurations" and confirm state. The exposed contract has a bounded state
route and a reviewed editable-file allowlist; it does not expose a general
configuration reader. Asked to distinguish facts from inference, it also
said facts are verified through "memory, files, or local authentication."
Authentication establishes caller access, not truth.

This is not an unsafe action path, but it can cause an external agent to
over-credit a concise answer with evidence it does not contain.

SUGGESTED EDIT (not applied)
  Add a fixed /ask context line that it has no general configuration reader,
  that memory and library results are candidates rather than verification,
  and that it should say "I infer" where it cannot cite an exposed source.
  A response field that distinguishes model text from route-provided evidence
  would make the boundary machine-readable.

The prior high-severity case remains valid: it was observed in an earlier

13. History-reference answers now fail closed before model sampling [IMPLEMENTED]
================================================================

The earlier failure has a concrete cause: the /ask path supplied the model
with an advisory statement that it cannot see live conversation history, but
still let the model generate an answer to vague history questions. A sampled
model answer can ignore an advisory even when it has no relevant context.

The source now detects a short set of literal history-reference phrases,
including "last time", "previous conversation", "we discussed", "you said",
and "before this request". Matching /ask requests return a fixed, accurate
boundary response with history_limited: true and do not reserve the director
slot or call the model at all. Ordinary questions remain unchanged.

The targeted interface, /ask, and semantic-retrieval tests all passed (32
tests). This edit is intentionally inactive in the already-running Sable
process until a later operator-controlled restart.


================================================================
14. Reversed history questions are covered too [IMPLEMENTED]
================================================================

The original literal guard did not match the natural reversal "What did you
tell me earlier?" It now recognises both "what did you say" and "what did
you tell me", with a regression test proving neither reaches the director.
The live Sable endpoint ended before it could be sampled again; this is a
deterministic source-and-test fix, not a claim about a fresh model sample.
